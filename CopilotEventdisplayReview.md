## Bugs fixed

### 1. `IrfExtractor.py` — `if not azimuth` fails for azimuth = 0° (North)

**Severity:** High — silently rejects valid North-pointing observations.

`extract_irf()` guarded against a missing azimuth argument with:

```python
if not azimuth:   # True for azimuth=0 (valid North direction)
    raise ValueError
```

`not 0` evaluates to `True` in Python, so any run with an average azimuth of 0°
(telescope pointing North) would raise a `ValueError` instead of proceeding.

**Fix:** `if azimuth is None:`

---

### 2. `IrfExtractor.py` — broken `logging.error` calls in `extract_irf_2d`

**Severity:** Medium — exception type is never logged; Python emits its own
logging-subsystem warning instead.

```python
# Before — second argument is ignored (no %s placeholder)
logging.error("Unexpected error:", sys.exc_info()[0])
logging.error("Entry number ", i)
```

```python
# After — single, correctly formatted message
logging.error("At entry number %d unexpected error: %s", i, sys.exc_info()[0])
```

---

### 3. `IrfInterpolator.py` — legacy azimuth-0 coordinate check breaks interpolation

**Severity:** High — any run with azimuth = 0° raises `ValueError` before any
interpolation is attempted.

A leftover branch from an older API required 4 coordinates when `self.azimuth == 0`,
while callers always pass 3 coordinates `[pedvar, zenith, offset]`:

```python
# Before — dead/wrong legacy check
if self.azimuth == 0:
    if len(coordinate) != 4:   # always True → always raises
        raise ValueError
elif len(coordinate) != 3:
    raise ValueError
```

```python
# After — single, correct check
if len(coordinate) != 3:
    raise ValueError
```

### 4. `util.py` — `getGTI` string/int comparison (latent)

**Severity:** Low — currently latent because trailing zeros are stripped first,
but logically incorrect.

```python
if (time_array_sec[-1] != 0):   # str != int → always True in Python 3
```

**Fix:** `if time_array_sec[-1] != "0":`

### 5. `util.py` — `getGTI` crashes on a fully-masked run

**Severity:** Medium — a run where every second is masked (all bits = 0) strips
the entire `time_array_sec` string to empty, then `time_array_sec[0]` raises
`IndexError`.

**Fix:** Guard added immediately after stripping:

```python
if len(time_array_sec) == 0:
    logging.warning("Time mask is all zeros: ontime=0, no GTIs")
    return np.array([]), np.array([]), 0
```

---

### 6. `util.py` — `WrongIrf` exception raised without required arguments

**Severity:** Medium — `raise WrongIrf` in error-handling paths would produce
`TypeError` instead of the intended custom exception.

```python
# Before — constructor required two positional args
class WrongIrf(Exception):
    def __init__(self, message, errors):
```

```python
# After — both args optional
class WrongIrf(Exception):
    def __init__(self, message="", errors=None):
```

### 7. `fillEVENTS.py` — empty event list after filter not handled

**Severity:** Medium — if an event-selection filter (`--evt_filter`) removes
all events, `np.max` and `np.mean` on empty arrays raise `ValueError` with a
cryptic message.

**Fix:** Explicit check added after mask application:

```python
if np.sum(mask) == 0:
    logger.error("Empty event list after applying selection filter")
    raise ZeroLengthEventList
```

### 8. `v2dl3_for_Eventdisplay.py` — `%d` format used for a string value

**Severity:** Low — `fname_base` is a string (e.g. `"run64080"`), but the log
message used `%d` (integer format), raising `TypeError` when
`--filename_to_obsid` is used.

**Fix:** Changed to `%s`.

## Efficiency improvement

### `fillEVENTS.py` — redundant `Time` objects in `__get_start_stop_times`

`t_avg` was computed by constructing three additional `astropy.Time` objects
that duplicated the already-created `t_start` and `t_stop`:

```python
# Before
t_avg = (
    Time(start_mjd, format="mjd", scale="utc")
    + (
        Time(stop_mjd, format="mjd", scale="utc")
        - Time(start_mjd, format="mjd", scale="utc")
    ) / 2.
)

# After
t_avg = t_start + (t_stop - t_start) / 2.0
```

## Documentation & code-quality improvements

### `fillRESPONSE.py` — removed dead debug code (~45 lines)

`fill_direction_migration` contained a permanently-disabled test path
(`test_psf = False`) that imported `scipy.stats.halfnorm` inside the function,
computed a synthetic half-normal PSF, and contained commented-out `print`
statements. This code was never executed and added significant noise. It has
been removed; the active PSF normalisation logic is unchanged.

---

### `fillRESPONSE.py` — `check_parameter_range` docstring numbering

The docstring listed steps starting at index 0 (unusual for prose documentation).
Changed to start at 1.

---

### `util.py` — `getGTI` docstring parameter name

The docstring referred to the parameter as `maskBits` (matching the ROOT tree
key name), while the actual Python parameter is `BitArray`. Corrected.

---

### `v2dl3_for_Eventdisplay.py` — `--filename_to_obsid` help text

Clarified that `OBS_ID` is set to the output **basename** and stored as a
**string** (not an integer run number):

```
Override OBS_ID with the output filename basename (stored as string).
```

---

### `fillEVENTS.py` — consistent use of module logger

Several functions used the root `logging` module directly instead of the
module-level `logger = logging.getLogger(__name__)`. All calls are now routed
through `logger`, which respects per-module log configuration. Log format
strings were also standardised to use `%`-style placeholders throughout.
